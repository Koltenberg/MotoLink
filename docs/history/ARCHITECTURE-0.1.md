# Переход от диагностики к регистратору поездок

## Решение

Для постоянной работы на iPhone основа — SwiftUI + CoreBluetooth. Bluefy служит
для первого короткого теста без macOS-сборки. У приложения не будет обязательного
аккаунта Kawasaki; в найденном открытом протоколе запросы идут прямо по BLE.
Возможность полного обмена без штатного приложения на EX500G остаётся проверить.

## Порядок разработки после первого JSONL

1. Подтвердить model-response и 0x40 на EX500G. Сопоставить capabilities с Z500,
   получить исходные 0x41 и при необходимости изучить 0x45.
2. Уточнить, как включается периодический поток. Не переносить неизвестные
   параметры init 0x08 только потому, что совпал UUID. Если короткие запросы
   не дают поток, нужен отдельный наблюдаемый тест расширенного init.
3. Для каждого показателя сверить значение и единицы с приборкой/условиями теста;
   добавить полученные, обезличенные EX500G-кадры в тесты. Не заменять их примерами Z500.
4. Добавить виджеты реальных значений с timestamp, статусами fresh/stale/unsupported.
   Разрыв связи не является нулевой скоростью или остановленным двигателем.
5. После устойчивой телеметрии подключить GPS и журнал поездок. Только затем
   измерять фоновую устойчивость и расход батареи на настоящем iPhone.

## Автоподключение

Первое сопряжение и разрешения выполняются при открытом приложении. Сохранить
идентификатор выбранного peripheral. Для знакомого байка использовать ожидающий
connect; при разрыве повторно ставить соединение в ожидание, если пользователь
включил автоподключение. При ручной остановке убрать ожидание и очередь команд.

CoreBluetooth: UIBackgroundModes=bluetooth-central, стабильный restoreIdentifier,
восстановление delegate, peripheral и подписок в willRestoreState. После рестарта
проверить сервисы/характеристики, не считать старое состояние подтверждением связи.
Если нужен scan, фильтр по реально рекламируемому UUID 99EB13AC…; 92FAEC07…
обнаруживается уже после соединения и не является правильным рекламным фильтром.

Сценарий «пришёл к байку — подключилось» технически поддерживается механизмами
Apple, но не равен гарантированной бесконечной работе. Принудительное закрытие
приложения пользователем препятствует восстановлению. Фоновое обнаружение бывает
медленнее. Поведение после выключения Bluetooth, перезагрузки и обновления iOS
включить в испытания; после перезагрузки учитывать первый unlock.

## Что считать поездкой

Разделять: байк виден → BLE связан → протокол отвечает → двигатель работает →
поездка началась. BLE-реклама/связь подтверждают доступность модуля, не работу
двигателя. RPM>0 означает работу двигателя только после проверки декодирования.
Начало движения определять по подтверждённой скорости/качественному GPS с
небольшим устойчивым интервалом, не по одному пакету. Порог подобрать по записям.

При остановке на светофоре поездку не закрывать. При кратком обрыве сохранять
пробел и продолжать ту же поездку. Завершение по длительному отсутствию данных
и движения — отдельная настраиваемая эвристика, а не вывод из Disconnect.

GPS подключать отдельным разрешением для реального маршрута. Не записывать его
круглосуточно. Требования CoreLocation к фоновому запуску/авторизации проверить
на этапе реализации: наличие BLE background само по себе их не заменяет.

## Данные и интерфейс

Локальная база SQLite: Ride, Sample, ConnectionEvent, CapabilitySnapshot,
ProtocolVersion. Для каждого sample: измеренное значение, единица, источник,
время, качество и raw-frame reference. Потерянные промежутки не интерполировать
молча. Raw-журнал хранить с лимитом; зафиксированные поездки не удалять по тому
же лимиту, что диагностические логи.

Экран: связь/последнее обновление; доступные показатели; запись поездки; история
маршрутов. Экспорт GPX для маршрута, CSV для телеметрии и JSONL для отладки.
Google Диск используется для материалов разработки; облачная отправка поездок
не является обязательной частью работы приложения.

## Перед общим выпуском

Проверить EX500G на нескольких циклах зажигания, блокировке экрана, временной
потере связи и перезапуске приложения; измерить батарею и объём журнала.
Публичную совместимость заявлять по протестированной модели/году/приборке.
Z500 и TFT-модели не объявлять поддержанными по совпадению UUID.

Сохранить атрибуцию Apache-2.0, собственное имя/оформление, описать локальные
данные и экспорт. Публичный релиз через App Store/TestFlight готовить после
полевой проверки. Сейчас материалы и приложение приватные.
