# MotoLink — установка на iPhone и работа в фоне

Проверка источников: 20.09.2026. Целевое устройство: iPhone 15 Pro Max. Bluefy уже обеспечивает рабочий транспорт для коротких проверок; это не подтверждает работу нашего нативного приложения в фоне.

## Решение для личного тестирования

**Если своего Mac нет, рекомендую: сборка unsigned IPA на стандартном macOS runner GitHub Actions → подпись и установка через Sideloadly на Windows.** Это реальный путь без покупки Mac и без платного Apple Developer Program. Но он требует доступа к GitHub и нескольких действий владельца iPhone. Сам файл IPA нельзя установить обычным открытием ссылки в Safari.

Сейчас в рабочей среде Linux. Повторно проверено: `xcodebuild`, `swift`, `gh` отсутствуют; среди доступных инструментов нет подключённого GitHub, macOS builder или сервиса подписи iOS. Поэтому подготовка workflow/исходников не означает, что сборка уже выполнена. Текущий блокер установки — реальный запуск Xcode-сборки и подпись для устройства, а не дополнительный визит к мотоциклу.

### Порядок без личного Mac

1. Загрузить чистый проект в **приватный** репозиторий GitHub. Логи, VIN, PIN, документы владельца и скриншоты в репозиторий сборки не нужны. Публикация исходников — отдельное последующее решение.
2. Запустить подготовленный workflow вручную (`workflow_dispatch`) на стандартном `macos-15`. Он проверяет проект, собирает для `generic/platform=iOS` с `CODE_SIGNING_ALLOWED=NO`, упаковывает `Payload/MotoLink.app` и отдаёт unsigned `.ipa` как артефакт. Ключи и пароль Apple в CI не требуются. Успехом считать только зелёный реальный запуск и полученный артефакт; исправлять ошибки по его логу.
3. На Windows установить [Sideloadly с сайта разработчика](https://sideloadly.io/) и необходимые Apple iTunes/iCloud-компоненты по инструкции этого сайта. Первая установка — через USB, с разблокированным iPhone и подтверждением доверия компьютеру. IPA и Apple Account вводятся локально в Sideloadly, не в переписке и не в GitHub secrets.
4. На iPhone подтвердить профиль разработчика, включить Developer Mode, если система его требует, и запустить MotoLink. Developer Mode требует перезапуска и подтверждения владельцем. [Инструкция Apple](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device/).
5. Проверить подпись и повторное открытие дома; только затем идти к мотоциклу. Бесплатная подпись действует 7 дней. Sideloadly умеет обновлять её через работающий компьютер; для Wi-Fi нужны общая сеть и предварительное USB-сопряжение. Это не продление «само по себе» без доступного ПК. [Возможности и условия Sideloadly](https://sideloadly.io/).

GitHub предоставляет стандартные macOS runners, в том числе для приватных репозиториев. У GitHub Free есть квота Actions; превышение может быть платным при настроенной оплате. Для одного небольшого проекта обычно достаточно квоты, но её остаток аккаунта здесь не проверен. Использовать ручной запуск, короткое хранение артефакта и лимит времени job; не включать платные larger runners. Без платёжного метода GitHub останавливает расход после квоты. [Runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [тарификация](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

Если Mac доступен, путь короче: открыть `ios/MotoLink.xcodeproj`, выбрать свой Personal Team, подключить iPhone и выполнить Run. Apple допускает личное тестирование без членства; профиль Personal Team тоже истекает через 7 дней, установлено может быть до трёх таких приложений на устройство. [Apple Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account).

AltStore Classic — запасной бесплатный вариант установки с Windows, если Sideloadly несовместим с конкретной конфигурацией. Он добавляет AltServer на ПК и AltStore на телефон, поэтому для одного MotoLink шагов больше. Также требует обновления подписи каждые 7 дней. [Официальная установка Windows](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows), [срок подписи](https://faq.altstore.io/altstore-classic/your-altstore).

## Что должно происходить в фоне

| Ситуация | Ожидаемое поведение и предел |
|---|---|
| Телефон заблокирован, приложение ранее настроено | `bluetooth-central` позволяет обрабатывать BLE-события; экран держать включённым не требуется. Это не бесконечный фоновый цикл. |
| Байк временно выключен/вне связи | Для запомненного peripheral оставить ожидающий `connect`. Apple не задаёт ему обычного таймаута; повторное появление устройства может завершить соединение. |
| iOS выгрузила процесс | Нужны стабильный restoration identifier, восстановление manager при запуске, `willRestoreState` и восстановление подписок. Есть ожидающее BLE-событие — есть основание для восстановления. |
| Пользователь смахнул приложение | Автоматическое восстановление не гарантировать: Apple указывает отсутствие BLE-relaunch после force quit. Открыть приложение снова. |
| Переключили Bluetooth или перезапустили телефон | Предусмотреть восстановление после открытия. По таблице Apple переключение питания Bluetooth мешает relaunch; после перезагрузки нужен первый unlock. |
| Радиосвязь есть, ответов протокола нет | Показывать «Подключён / ожидаем данные»; не подставлять нули вместо неизвестных показаний. |

Основание: [Core Bluetooth Background Processing](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html), [Apple QA1962](https://developer.apple.com/library/archive/qa/qa1962/_index.html). Последний документ относится к iOS 11 и служит документированной границей обещаний; поведение актуальной iOS всё равно проверяется на физическом телефоне.

**Фильтр поиска:** для фонового сканирования Apple требует явный список рекламируемых UUID. В полученных скриншотах EX500G рекламирует `99EB13AC-42C9-4745-8B76-C30141401CE5`; сервис данных `92FAEC07-C075-4B7C-A6C2-BBD1D1A150F5` обнаруживается после соединения. Подмена первого вторым может привести к тому, что фоновый поиск не увидит байк. Первый выбор устройства допустим в foreground; дальше предпочтителен сохранённый peripheral UUID и pending connect. [Текущая документация scanForPeripherals](https://developer.apple.com/documentation/corebluetooth/cbcentralmanager/scanforperipherals(withservices:options:)).

**Для разработчика:** менеджер Bluetooth должен создаваться и при запуске процесса в фоне, без необходимости открыть экран. Проверять этот путь отдельно; UI `StateObject` сам по себе не считается проверкой relaunch. Сохранять события локально сразу, восстанавливать режим пользователя и разделять готовность BLE, подписок и протокола. Команды включения потока повторять после reconnect только если их смысл уже подтверждён и пользователь включил запись.

## GPS и определение поездки

BLE-автоподключение и GPS — разные механизмы. `bluetooth-central` не даёт приложению разрешения на геопозицию. Для маршрута через `CLLocationManager` нужны permission, `UIBackgroundModes: location` и `allowsBackgroundLocationUpdates = true`. When In Use достаточно для продолжения в фоне записи, начатой при открытом приложении. Отдельно проверить полностью автоматическое начало нового маршрута из фонового BLE-события; не выдавать этот сценарий за уже работающий. [Apple: background updates](https://developer.apple.com/documentation/corelocation/cllocationmanager/allowsbackgroundlocationupdates), [пример записи пути](https://developer.apple.com/documentation/MapKit/displaying-an-updating-path-of-a-user-s-location-history).

Для автоматического режима предусмотреть отдельное объяснение и запрос Always, восстановление активной сессии и понятный признак записи. На новых версиях ОС Apple также описывает `CLBackgroundActivitySession`/`CLServiceSession`; при минимальной iOS 16 нужна проверка availability и совместимый путь. После нового запуска процесса восстановить нужные сервисы, а не полагаться на прежний объект location manager. [Текущее руководство Apple](https://developer.apple.com/documentation/corelocation/handling-location-updates-in-the-background).

Наше проектное решение: BLE-соединение открывает сессию наблюдения; начало движения определяется подтверждённой скоростью/движением, работа двигателя — подтверждёнными RPM. Включённая приборка не равна заведённому двигателю. При кратком пропадании BLE сохранять разрыв внутри поездки; GPS включать только для запрошенной записи, не держать постоянно ради работы таймеров. Показания телефона и байка хранить с указанием источника.

## Один следующий визит вместо серии коротких

До визита завершить: реальную компиляцию, установку, первый запуск, разрешения, экспорт пробного журнала и повторное открытие приложения. Основные декодеры и ветки ошибок проверить на уже сохранённых пакетах и фикстурах.

Одна сессия у байка должна собрать: подключение и модель/возможности; ответы потока в открытом приложении; несколько минут с заблокированным экраном; выключение/повторное включение зажигания и восстановление; единый экспорт с отметками этапов. Проверять без подключённого Xcode debugger, чтобы его влияние не скрывало фоновые ограничения. Отдельная дорожная запись нужна только после подтверждения чтения и фонового сохранения. Задержку reconnect, расход батареи и полноту телеметрии нельзя честно вывести из спецификации — это измеряемые результаты теста.

## Бесплатность для пользователей и публичный выпуск

Личное тестирование можно оставить бесплатным с еженедельным обновлением подписи. Для удобной массовой доставки через App Store/TestFlight нужен издатель с Apple Developer Program: стандартная плата Apple — 99 USD в год, локальные условия могут отличаться. Бесплатная цена самого MotoLink не отменяет этот расход издателя. До проверки совместимости EX500G регистрация и оплата не нужны. [Apple: enrollment](https://developer.apple.com/help/account/membership/program-enrollment/).

На этом этапе новые аккаунты не созданы, платные услуги не включены, сторонним лицам ничего не отправлено. Сборка, подпись и фактическое поведение на iPhone остаются отдельными проверяемыми этапами; подготовленные инструкции не подменяют их выполнение.
