# Архитектура MotoLink 0.3

Нативный клиент iOS: SwiftUI → MotoLinkController → MotorcycleBluetooth и RideRecorder.

MotorcycleBluetooth создаётся при запуске приложения, хранит peripheral, использует ожидающее соединение и восстановление CoreBluetooth. После трёх Notify подписок выполняется последовательность известного протокола; при отсутствии полноценного 4A один раз используется полный запасной профиль. Входящие кадры сохраняются с временем. Основные ответы и этапы закрепляются отдельно от вращающегося журнала.

RideRecorder принимает GPS CoreLocation и отдельно телеметрию мотоцикла. Точки маршрута, разрывы, данные и компактное описание поездки сохраняются локально. История отображает карту; экспорт даёт GPX и JSON. Автозапись разрешается переключателем и необходимыми разрешениями iOS. Фоновое время ограничивает система; force quit не приравнивается к обычному сворачиванию.

Веб-клиент: отдельные ES-модули ble.js, diagnostic.js, protocol.js, storage.js, rides.js и app.js. Полные пакеты хранятся в IndexedDB; видимый журнал ограничен отдельно. При отказе хранилища используется явно обозначенный резерв с лимитом и счётчиком потерь. Старые журналы v0.1/v0.2 сохраняются в полном экспорте.

Запросы сериализованы. ATT-доставка, протокольный ACK и пакет измерений различаются. Текущие показания требуют capabilities текущего подключения; устаревшие данные скрываются. GPS телефона никогда не заменяет показатель скорости колеса без отдельной подписи.

Веб восстанавливает связь лишь пока страница работает, не обещает системного пробуждения на iOS. Поэтому конечный путь пользователя — нативное приложение.
